Final Results: Positional Encoding Frequency and Width Variations

Here you can see a visual representation of how the width and positional encoding of of the network affects the images. If not enough frequency information is given, the image loses sharpness and is blurry. Conversely, it gets a bit too sharp when the positional encoding is blown up.

The width is the number of parameters in each layer of the network. When this variable is too small, the network cant store the full information of the image and fails to capture color details especially. When this is too large, the image actually is great, but there is risk of overfitting with more difficult tasks and training will take much longer.

Part 2: Fit a Neural Radiance Field from Multi-view Images

Implementation

Now, I will be moving on towards a 3d representation and Neural Radiance Field. In order to do this, we now need to consider the depth, position, and viewing angle of each point.

Ray Sampling

For each pixel in an image, we can build a ray that passes through the camera center. This ray is how we will represent all of the data in our scene. To obtain these rays, we can use the extrinsic and intrinsic camera matrices we generated from before to construct each ray. Simply put, these matrices map the pixel coordinates to the 3d world coordinates. With the camera orientation also contained in the extrinsic matrix, we can construct a ray in space.

Model Feedback and Volume Rendering:

Them magic to this is the volume rendering equation. The equation is a model of how a point in space will look when viewed from a given angle. This varies on opacity. A similar idea to this is the density represented by the sigma value. After discretely adding up all of the points along a ray, we can guage the difference between the true color and the color predicted by the model.

\[\hat{C}(\mathbf{r}) = \sum_{i=1}^{N} T_i \left( 1 - \exp(-\sigma_i \delta_i) \right) c_i, \quad \text{where} \quad T_i = \exp\left( -\sum_{j=1}^{i-1} \sigma_j \delta_j \right)\]

Lego Set

The lego set is a set of images that can be seen with the dome visualization in the previous parts. There were many camera frames and they were all provided undistorted by lens effects, calibrated distance from the subject, intrinsics and extrinsics provided. With this set, we are able to get a fairly clean view of the lego set with minimal training. The only modifications I made were to add a gamma learning rate decay of .3. Besides this, it took 5000 iterations on batch size 10000 to reach 23+ PSNR.

Lafufu and Pikachu

Lafufu Video

The lafufu was a staff built data set with intrinsics pre-calculated. with this set I was able to achieve about 19 PSNR with 5000 iterations. I tweaked the learning rate to .3 decay and most importantly, the near and far I used were completely different. I used a near of .1 and a far of 1.0. This allows my rays to be set in a much tighter space and scan the subject only over and over rather than going through space.

In order to do this, it was important to set the origin. For my code I set the origin to be the corner of the Aruco tag closest to the lafufu's feet. This placed the origin of the scene very close to the subject so the rays could be limited in size. I tried larger parameters and the results were just worse. My final scene generation used a batch size of 20000, 64 samples per ray, and 5000 iterations.

Above is my attempt at creating a nerf. I think that one of the biggest things that I struggled with was the lens of my camera. The images were quite distorted and the best estimation for my origin came from setting the size of the aruco tag in the scene to be larger than it actually was due to this.

I trained 3000 iterations in this video with a batch of 15000 and 64 samples. I think one of the best ways to improve this would be to use a better image set with more aruco tags. Additionally, due to the placement of the single aruco tag, the back of pikachu is pretty much never trained.
